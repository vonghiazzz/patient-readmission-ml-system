# Patient Readmission API Contract

## Contract status

This document defines the Phase 2 request and response contract for API version
`v1`. The endpoint still returns an explicitly marked mock result until the
versioned model bundle is delivered in Phase 3.

The contract follows the current DATA-07 preprocessing metadata. Member A must
review the data-field mapping and Member B must review compatibility with the
model handoff before the production model is integrated.

## Endpoint

`POST /api/v1/predict`

The request contains only features available at or before discharge. The API
forbids unknown fields so identifiers or targets cannot silently enter the
model input.

### Required fields

| Field | Type | Constraint |
| --- | --- | --- |
| `gender` | string | Non-empty |
| `age` | string | Non-empty age interval |
| `time_in_hospital` | integer | At least 1 |
| `num_lab_procedures` | integer | Non-negative |
| `num_procedures` | integer | Non-negative |
| `num_medications` | integer | Non-negative |
| `number_outpatient` | integer | Non-negative |
| `number_emergency` | integer | Non-negative |
| `number_inpatient` | integer | Non-negative |
| `number_diagnoses` | integer | Non-negative |

The remaining fields in the OpenAPI `PredictionRequest` schema are optional
categorical or encounter-context features. Missing optional fields are passed
as null for handling by the trained preprocessing pipeline.

### Explicitly excluded fields

- `encounter_id` and `patient_nbr`: patient/encounter identifiers.
- `readmitted` and `readmitted_30d`: source and derived targets.
- `service_utilization` and `total_clinical_activities`: generated by the
  preprocessing pipeline from raw counts; clients cannot override them.

```json
{
  "race": "Caucasian",
  "gender": "Female",

```

### Phase 2 mock response

```json
{
  "readmission_probability": 0.0,
  "predicted_readmission": false,
  "risk_band": "mock",
  "threshold": 0.5,
  "model_version": "mock-phase-2",
  "is_mock": true
}
```

Production responses must set `is_mock` to `false` and expose the real model
and threshold versions after the Phase 3 model handoff.

## Error contract

Errors use one envelope and never echo submitted values:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Request validation failed.",
    "details": [
      {
        "location": ["body", "number_inpatient"],
        "message": "Input should be greater than or equal to 0",
        "error_type": "greater_than_equal"
      }
    ]
  }
}
```

| HTTP status | Meaning |
| --- | --- |
| `422` | Request violates the schema or contains a forbidden field |
| `500` | Unexpected internal failure; response contains no stack trace |
| `503` | Required model artifacts are unavailable |

## Operational endpoints

- `GET /health`: the API process is running.
- `GET /ready`: reports the current mock/model-loading state.
- `GET /docs`: interactive Swagger documentation.
- `GET /openapi.json`: machine-readable contract.
